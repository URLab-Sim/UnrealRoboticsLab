# MJCF authoring requirements and implementation status, 2026-10-02

This records user requirements and remaining proof points. The authoring implementation may reuse code by responsibility; no old ProtoSpec AST or wrapper is retained merely because it existed. Current code is evidence about workflows and defects. It complements [the intended system boundary](intended_design.md): editor authoring may produce MuJoCo models, while world-owned simulation and the neutral renderer remain usable without `MjManager`, `MjArticulation` or an authoring Blueprint.

## Required behavior

- **Import or create:** import an existing MJCF XML document, or create a new MJCF model inside Unreal. XML → Blueprint import is available through an Editor action and an authoring import RPC; both invoke the same operation and produce the same persistent assets and diagnostics. Import should be transactional, with reported partial failures and no silently half-authored Blueprint. Both paths support edit/export and use in Blueprint assets or levels.
- **Bidirectional authoring semantics:** import, edit and export must retain the meaningful MJCF constructs and settings supported by the shipped MuJoCo parser. In particular, a `<position>` actuator must remain a position actuator rather than silently becoming a different authored construct. Source spelling and alternate orientation forms need not be exact: explicit, documented conversion such as `fromto` to an Unreal preview transform is acceptable when it preserves editable inheritance. Comments and formatting need not survive. Tests must state each allowed normalization and check the resulting model and editable settings.
- **Native typed UE authoring and code access:** easy creation and editing in the Blueprint editor and levels, plus typed Blueprint and C++ access, are required. Users work with meaningful component/property types, enums, numeric fields and filtered references, not raw XML or arbitrary string maps. A motor's joint target should be selected from eligible joint components in the relevant authoring graph. Internally, references need stable target identity across rename, Blueprint inheritance and instance edits. Copying a reference preserves its selected target; it does not implicitly retarget to a same-named element inside a duplicated subtree. Users can explicitly rebind a copied reference. Export resolves selected identities to MJCF names, and import resolves names back to typed targets or reports ambiguity/missing targets. The editor must expose invalid or unresolved references instead of silently changing them.
- **Authored hierarchy and preview:** the Blueprint authoring view mirrors MJCF's model, asset definitions (such as mesh and texture), and worldbody with bodies and geoms. Asset nodes are shared resources, not visible scene instances. Geoms reference those nodes and show editor previews at their geom/body transforms. This preview exists before runtime compilation; its backend is an implementation choice. Once the authored model is compiled, the existing MuJoCo adapter supplies the neutral renderer. Authoring components do not remain a parallel runtime render scene.
- **Native spatial editing and units:** translation, rotation and scale use Unreal's transform gizmo and Details controls as the active authoritative spatial state. Raw MJCF `pos`/`quat`/`euler`/`size`/`fromto` fields must not appear as competing editable controls for the same state. Shared spatial conversion maps generated MJCF descriptors to and from native transforms, respecting parent-local order, defaults and shape-specific size rules. Serialized MJCF sent to the compiler uses canonical radians for angles; native Unreal editing uses centimeters and degrees. Conversion must cover compiler-angle-dependent attributes and defaults, including relevant joint limits and mixed-DOF cases, without multiplying every numeric field blindly. Upstream schema lacks complete unit semantics, so bounded audited metadata must identify semantic categories. Primitive scale must map only to representable MJCF sizes; mesh intrinsic scale and geom instance scale are distinct. Parent shear, negative scale or other unrepresentable transforms must be diagnosed rather than silently exported. Axes/endpoints need appropriate visual handles; exact supported edits remain a proof gate. Nonspatial physics fields, including friction, mass, controller gains and joint limits, remain typed properties with correct units.
- **Editable MJCF spatial defaults:** importing XML must preserve default-class relationships. A geom or site that inherits `fromto`, pose, or size must continue to reflect changes to the relevant `<default>` class until that element is explicitly edited. An explicit element edit creates a visible local override for the edited spatial value; resetting that override restores inheritance. Import must not silently materialize inherited spatial values as local overrides merely to supply Unreal's transform preview. Import normalizes `fromto` into a type-neutral UE half-extent value and discards its endpoints. Export maps that value through the effective shape while preserving the initial compiled model; subsequent type changes operate on the normalized dimensions. This rule concerns MJCF `<default>` classes; inherited Blueprint content and placed-instance overrides are separate scopes with their own merge rules.
- **Spatial Details controls:** on a concrete scene element, Details presents Unreal's native location and rotation controls instead of duplicate generated `pos`, `quat`, `fromto`, or Euler controls. It presents native scale instead of generated `size` only when the element's shape has a supported scale-to-size mapping. Other `size` attributes remain available. When a native spatial value is locally authored, Details offers a separate Restore inherited position, rotation, or size action that clears the corresponding authored field; Unreal's ordinary transform Reset does not clear that MJCF presence. On a geom or site partial inside `<default>`, the generated spatial attributes remain visible and editable because that template has no live scene transform; the panel identifies them as inherited class settings. Hiding a Details row must not remove its generated authored storage or Blueprint/C++ accessors.
- **UE class hierarchy support:** inherited Blueprint authoring content, derived-class additions/overrides, and placed instances must have defined, reproducible merge and serialization behavior. Editing one level instance must not silently mutate a Blueprint asset. Assets and level-authored scenes must both remain valid authoring inputs.
- **Persistent authored assets:** recursively resolve imported includes and referenced assets into persistent UE assets/packages referenced by the Blueprint. After import, the Blueprint and its UE assets/typed numeric fields are the sole authoring source of truth: no original XML, include, model, mesh, texture, heightfield, skin, or other source bytes/paths may be required or retained as a fallback. Save/reopen/cook and compilation must work after the original source files are removed. A transient or persisted compile cache is allowed only when regenerated from the current authored UE state during compile/export/cook; it must not contain original-source replay data. Includes expand into the imported authored graph. Native `<asset><model file="...">` attachments remain native attachments but resolve through references to separately editable child Blueprints. Persisted native model-file payloads are not a substitute for editable authored assets. Use specialized typed `UStaticMesh`/`UTexture` assets when they faithfully represent the data, and appropriate typed persistent UE assets or editable numeric fields for other supported resource kinds. Arbitrary formats are not assumed representable; unsupported data must fail import clearly rather than be silently dropped or retained opaquely. Users may author new MJCF `<asset>` entries from their own Unreal assets, explicitly including `UStaticMesh`, via typed Content Browser pickers; supported material/texture scope needs a decision. Geoms reference stable authored asset-node identities. Converting selected assets into compiler-ready geometry is internal; users do not manually export files. Preserve LOD0 MeshDescription visual triangles, authored per-corner normals when present, and UVs. If normals are entirely absent, omit OBJ normals and let MuJoCo apply its native missing-normal behavior; partial normal data fails closed. This does not promise parity with normals Unreal generates for the built LOD under recompute-normal settings; exporting built-render topology/normals remains a follow-up because it would change the current source-MeshDescription geometry/build-scale contract. Per-geom `contype`/`conaffinity` masks and explicit contact pairs inform collision-data needs for each use of a shared asset. Both masks zero excludes ordinary mask-based collisions, but an explicit pair may still require collision data; one zero mask alone proves neither noncollision nor a decomposition choice. Visual and collision sources may differ only by an explicit policy, with preview and compiled/exported geometry checked for unintended mismatch. Conversion, refresh, cook closure and diagnostics must be coherent for import and new-Blueprint workflows. Arbitrary Unreal material graphs are not assumed invertible into MJCF.
- **Editor-centered workflow with separate runtime control:** the Editor action and authoring import RPC call the same import operation. The RPC is an editor authoring entry point, not a redesign of the existing source-independent runtime API used by Python and other controllers; a general remote authoring system is not required.
- **Cookable authored scenes:** authored UE assets/Blueprints and level placements may run in a packaged game with Blueprint code access. Data types, generated classes and the compile/load handoff needed for that use cannot be blanket editor-only. The cooked representation must include the model and referenced asset bytes needed to run; editor-only filesystem paths are insufficient. Packaged creation/editing tools or a general packaged authoring system are not required. Details panels, import UI and editor transactions may remain in `URLabEditor`; runtime model ownership still belongs to the independent simulation service.
- **No runtime authoring dependency:** an external XML/MJB/MJZ or neutral render source must continue to load and run without authoring components. A proposed editor-to-runtime link cannot reintroduce mandatory articulation actors, actor-based state addressing or robot-group control facades.

## Desired behavior, not yet committed

- A typed, explicit binding from an authored element/property to the active compiled model could let Blueprint/C++ code change a setting such as geom friction, possibly by validated model replacement/recompile. Editor scene components are authoring interfaces, not runtime owners. The UI should explain whether a change affects an asset/class default, an inherited Blueprint default, a level-instance override, or only a play instance. An explicit apply/save-back path may bridge these scopes, subject to Unreal undo/transactions, model validation, state migration and control ownership. Persistence policy is undecided.
- The [lead proposal](authoring_design_proposal.md) uses generated metadata/accessors from a **pinned, runtime-compatible** MuJoCo schema where authoritative. The requirement is a clean typed Unreal Details/Blueprint/component experience with minimal duplicated handwritten MJCF semantics; today's generated classes need not be retained.

## Current implementation and remaining limits

**Accepted source-of-truth decision (2026-10-02; supersedes the captured-source implementation described below):** authored Blueprints and their referenced UE assets/editable numeric fields are the only persistent source after import. The prior `SourceResources`/`SourceAssetBindings` design and source-byte replay are not an acceptable final architecture. Generated-only compiler payloads may be cached, but must be rebuilt from current UE authored data and must not preserve original XML or resource bytes. Includes are expanded; native nested-model attachments should point to editable child Blueprint assets. Regardless of authoring representation, compilation must produce the same native MuJoCo model and install through the existing physics service, MuJoCo adapter, and neutral renderer; no authoring-only simulation or rendering path is allowed.

This work covers editor authoring and native scene/model compilation. Task logic, Blueprint behavior, runtime name/ID bindings, and simulation orchestration extensions belong to a separate layer and must not be added here.

The remaining resource materialization work is explicit: `mesh.file` and ordinary `texture.file` already have UE import paths but must be generated afresh from the current authored assets, with cube texture faces represented separately for `fileright`, `fileleft`, `fileup`, `filedown`, `filefront`, and `fileback`; `hfield.file`, `skin.file`, and `flexcomp.file` must become typed UE assets or editable generated fields; `model.file` must become an editable child-Blueprint reference; and QuickConvert collision hulls must be represented by inline authored geometry or UE mesh references. No resource kind may fall back to retained source bytes.

The generated UE component tree is the only persistent authoring document. The direct XML importer and writer use generated presence, parse/format, child-context and reference descriptors for both SCS templates and live actors. Includes are expanded with source diagnostics; ordinary upstream aliases remain raw generated fields, and the MuJoCo native XML parser constructs the sole `mjSpec` before compilation. The plain generated AST, generic profile SDK and generic reader/writer have been removed. The runtime renderer remains independent of authoring components.

Spatial import consumes alternate orientation spellings and `fromto` once. Original `fromto` endpoints are not retained or reconstructed. A geom/site or default partial normalized from `fromto` stores one optional, atomic `MjSpatialHalfExtentsCm`: radial X/Y and axial Z half-extents in centimeters. Effective default-class layering keeps that normalized value live; a local complete size overrides it atomically, and clearing the local override restores inheritance. Export maps the effective normalized extents to the current effective shape's `size`. Changing type after import follows the stored UE dimensions and new shape mapping, not a reinterpretation of source endpoints. Initial compiled-model parity and post-edit normalized semantics are separate tests.

Generated reference fields still store names (`TOptional<FString>`) as the XML-facing value. Editor data also stores selected targets in a `ReferenceTargets` sidecar keyed by UE `FComponentKey`; current rename traversal consults those identities. The fresh sidecar-specific inherited-Blueprint test passed after editor reconstruction. It covers child overrides without parent mutation, inherited and placed-instance target rename fixups, saved/reloaded reference identity, and fail-closed handling after target deletion. Copying a referrer preserves its original selected target; implicit retargeting within a duplicated subtree is intentionally not part of the behavior. See the persisted [reference-graph test log](../../../audit_docs/implementation_runs/authoring_packaged_handoff_20261002/reference_graph_test.log).

The prior implementation captured original XML/dependency/resource bytes in `SourceResources`/`SourceAssetBindings`, reused unchanged bytes, and exported edited mesh/texture assets through transient component copies. Its tests established that this mechanism could survive hiding the source directory, but they did not establish the accepted authoring contract above: retained original bytes and source-path bindings violate the source-of-truth requirement. Replace those results with tests proving import materialization into editable UE data, deletion/absence of original sources, fresh generated resource output after edits, and native compile/install through the existing runtime path. The schema already marks `mesh.file`, `hfield.file`, `skin.file`, `texture.file` and its six cube-face files, `model.file`, and `flexcomp.file` as file resources; the asset sink/importer must materialize each supported kind rather than preserve its source bytes.

The generated alias descriptor also distinguishes native-ignored unknown attributes on `frame`/`replicate` from strict ordinary tags. The importer warns and drops those attributes, matching the pinned native reader's effective model; it does not add a per-element physics interpretation. Native MuJoCo still interprets ordinary shortcut spellings and defaults when parsing the emitted XML. The completed full import-factory audit covers saved Blueprint reload and source-hidden portable export for 893 full-model inputs; 889 matched natively with preview assets, one matched with KTX preview unsupported, and three retained strict BVH mismatches. Thirteen additional inputs were inert include fragments. See `audit_docs/implementation_runs/full_corpus_20260927/factory_portable_report.md` for the per-index evidence. A source trace confirms the Content Browser XML factory and editor `editor_import_xml` RPC converge on `ImportXmlSync`/the same factory operation. A scoped Development BuildCookRun for a 2x2-heightfield authored map passed (exit 0), and a negative cook with missing persisted `missing.obj` bytes failed (exit 1), confirming the current cook error path. Following the compile-only omission-marker fix for selected `MeshAsset` precedence, the focused `URLab.Authoring` automation filter passed 4/4, `URLab.Export` passed 5/5, and mesh preparation passed 1/1, including selected visual-mesh export without collision data. Logs are in [the packaged authoring evidence](../../../audit_docs/implementation_runs/authoring_packaged_handoff_20261002/README.md). The final staged game loaded the authored map and linked MuJoCo 3.11.1. Final `simulation_describe`/`simulation_observe` RPCs confirmed the source-hidden imported model at generation 1 (`nq=7`, `nv=6`, expected Blueprint joint, stable content SHA) and advancing step sequence/time after the latest mesh-precedence and missing-normal changes. The run used NullRHI, so it proves model installation and stepping, not rendered pixels. A 1x1 heightfield is currently rejected by the neutral renderer, which requires at least 2 rows and 2 columns; the positive packaged fixture uses 2x2. Broad live runtime bindings and save-back are optional design work, not committed requirements.
